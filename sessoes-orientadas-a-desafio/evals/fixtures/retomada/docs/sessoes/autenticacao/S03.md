# S03 — Refresh token com rotação e revogação

- **Demanda:** `autenticacao`
- **ADR:** [docs/adr/0001-autenticacao.md](../../adr/0001-autenticacao.md)
- **AMARRACAO:** [docs/sessoes/autenticacao/AMARRACAO.md](AMARRACAO.md)
- **Depende de:** S02
- **Tamanho estimado:** M

## Objetivo

Permitir que um usuário renove o access token usando um refresh token de uso único, com rotação e revogação do token anterior.

## Dentro do escopo

- `src/auth/token.ts`
- `src/auth/refresh.ts`
- `tests/auth/refresh.test.ts`
- migração de refresh tokens, se ainda não existir

## Fora do escopo (não tocar)

- tela de login (S04)
- auditoria de acessos (S05)
- login social
- rotação de chaves de assinatura

## Contexto mínimo para iniciar

Leia apenas:

- `src/auth/token.ts` — emissão e validação atuais
- `tests/auth/refresh.test.ts` — comportamento esperado do refresh
- `docs/adr/0001-autenticacao.md` — decisão sobre RS256 e escopo das sessões

**Não é necessário ler:** `src/ui/`, `src/audit/`, `src/payments/`.

## Critério de pronto

- [ ] `npm test -- tests/auth/refresh.test.ts` passa
- [ ] refresh token usado duas vezes é rejeitado e revoga a família de tokens
- [ ] token expirado retorna 401 com erro padronizado
- [ ] access token anterior continua válido até expirar

## Plano de execução

1. Modelar refresh tokens com hash, família e estado.
2. Implementar rotação e revogação.
3. Cobrir reuso, expiração e concorrência nos testes.

## Riscos e pontos de atenção

- Corrida entre duas requisições de refresh simultâneas → usar transação e janela de graça.
- Vazamento de token em log → nunca logar o valor bruto.

## O que o revisor deve olhar com atenção

- Estratégia de revogação em família.
- Tratamento de concorrência.
- Nenhuma mudança de contrato além do endpoint de refresh.
